# perf-flow

输入一个网址,测量它的加载过程:**TTFB、HTML 收完、FCP、LCP**,标注 FCP / LCP 对应的页面元素,并支持自定义"某个元素何时出现 / 消失"的检测。操作都在本地网页界面里完成。

> 状态:v0.1,早期版本。`package.json` 里保留了 `private: true`,避免误发布到 npm;目前通过 GitHub 获取。

## 运行

需要 Node.js 20+ 和本机已安装的 Google Chrome。

```bash
npm install
npm start            # 启动本地服务并自动打开浏览器界面
```

演示页面(不依赖外部网站,带延迟的 CSS、流式 HTML、大图、接口请求和"遮罩消失"):

```bash
npm run demo         # http://127.0.0.1:9090/
```

在界面里输入 `http://127.0.0.1:9090/`,添加几项检测即可体验。

命令行选项:`--port <n>`、`--no-open`、`--home <dir>`。环境变量 `PERF_FLOW_CHROME` 可指定 Chrome 路径。结果保存在 `~/.perf-flow/`。

## 测量方式

- 每一轮使用**全新的浏览器上下文**(冷缓存),不限速。默认 3 轮,汇总取**中位数**并给出范围。
- 默认使用有窗口的 Chrome(有 GPU);可在界面勾选"无头模式"。
- 可选的"画面标注"会**额外多跑一轮**并录屏,用于在截图上框出元素。它不计入上面的统计。
- FCP / LCP / TTFB 来自浏览器的 Performance API。

### 自定义检测

| 类型 | 含义 | 精度 |
|---|---|---|
| CSS 选择器 · 出现 | 元素存在且可见(图片需加载完成) | 约 1 帧 |
| CSS 选择器 · 消失 | 曾经可见,之后不可见或被移除 | 约 1 帧 |
| 页面文字 | 可见文本中出现 / 消失(忽略 script / style) | 约 1 帧 |
| 网络请求 | 地址包含关键字(`re:` 开头为正则)的请求开始 / 完成 | 精确(Resource Timing) |
| JS 表达式 | 表达式为真(如 `window.appReady === true`) | 约 1 帧 |

"约 1 帧"指:条件在某一帧被观察到,取下一帧的起点作为"用户看到"的时间,存在几十毫秒以内的误差。

## 加载时间线:依赖树与聚焦

时间线按"依赖链"排列,**每条链内部都按时间从早到晚,最后一行才是这个时间点本身**(FCP、LCP、DOMContentLoaded、load)。它上面缩进的行是决定或推迟它的东西,最晚完成的(决定者)紧挨着它,竖线把它们连到这个时间点:

- **FCP**:Chrome 标记为渲染阻塞的请求、FCP 之前无法识别的空白、FP。
- **LCP**:更早出现的候选在上,最后一行是最终 LCP。
- **DOMContentLoaded**:下一级是 HTML 解析完成(`domInteractive`)和 `defer` / `module` 脚本;同步脚本再缩进一级,排在“HTML 解析完成”之前。
- **load**:拖住它的请求(图片、样式表、字体、iframe、`async` 脚本、脚本注入的资源等)。
- “请求与服务器”和“你的检测”不是依赖关系,平铺显示。

条是请求的下载起止,**结束得最晚的标为“决定者”**。鼠标移到一条链上,链的左侧会出现浅色竖条。

为了不增加阅读负担,总览里每条链默认只展示前几条,**其余收起**,点链顶部的“展开其余 N 项”再看(收起的是更早完成的几项);父行、决定者、最终 LCP、无法识别、你自己设的检测始终显示。

**聚焦**:时间线右上角的 `总览 | FCP | LCP | …` 可以只看某一条链。聚焦后只显示“请求与服务器”和选中的那条链,明细全部展开(包括总览里隐藏的说明),时间轴也放大到这条链的范围。

## DOMContentLoaded 与 load 由什么决定

判断规则来自对 17 个构造页面的实测(每个页面只放一种东西),不是凭规范推断的:

| 在等什么 | 谁可能是决定者 |
|---|---|
| HTML 收完 → `domInteractive`(解析完成) | **同步脚本**(没有 `async` / `defer` / `module`);让后面脚本等待的阻塞样式表(只标为“可能”) |
| `domInteractive` → DOMContentLoaded | **`defer` / `module` 脚本** |
| DOMContentLoaded → load | 图片、样式表、字体、iframe、**`async` 脚本**、脚本注入的资源 |

另外:`fetch` / XHR / beacon **既不推迟 DOMContentLoaded,也不推迟 load**;屏幕外的懒加载图片不推迟 load。

**无法识别的部分画成带斜纹的横线**:资源下载完成之后的脚本执行、HTML 解析本身,Resource Timing 里没有记录。超过 150 ms 的空白会在时间线上画成一条“无法识别”的斜纹横线,起止就是这段空白的起止,位置紧接在决定者之后(FCP 之前的空白画在 FCP 链里)。不会把剩下的时间归给别的东西。

**同步脚本会阻塞什么,取决于它在哪里、在做什么**(实测):

| 情形 | FCP | LCP |
|---|---|---|
| 同步脚本在 `<head>` | 被推迟到脚本结束 | 被推迟 |
| 同步脚本在 `<body>` 末尾(下载中) | 不受影响 | 不受影响 |
| 同步脚本在 `<body>` 中间(下载中) | 不受影响(脚本前的内容先画出) | 脚本**后面**的内容晚出现,可能推迟 LCP |
| 内联脚本占住主线程(无论在哪) | 一起被推迟(连前面的内容也画不出来) | 一起被推迟 |

**`load` 事件什么时候触发**:文档解析完成之后,在途的、会拖住 load 的子资源(图片、脚本、iframe 等)数量降到 0 的那一刻触发,**只触发一次**。触发之后再发的请求不影响它。所以:
- 每隔一段时间请求一张图,只要请求之间有空档,load 会在空档里触发;之后的请求不再影响。
- 一连串首尾相接的图片、或互相重叠的请求,**load 可以一直不触发**。fetch / XHR 不会拖住 load。
- load 不触发时,这一轮**不会失败**:FCP、LCP、DCL、自定义检测照常测量,load 记为“未触发”,并列出观察结束时**仍未完成的请求**。汇总里如果只有部分轮次触发,会明说“只有 x/y 轮触发”,时间只来自触发了的那几轮。

**没有验证的**:`<video>` / `<audio>` / `<link rel=preload>` 等类型会不会拖住 load。这类请求会被单独注明“工具无法确认”,不参与决定者的判断。

DOMContentLoaded 和 load 的数值取**事件触发的时刻**;事件处理函数的耗时在悬浮卡片里单独显示。旧版本记录取的是事件结束的时刻,没有请求明细,界面会标明。

## 查看范围:汇总或单轮

结果区有一个固定在顶部的“查看范围”工具栏,同时控制卡片、加载时间线和元素表:

| 选择 | 卡片 | 加载时间线 | 元素表 |
|---|---|---|---|
| **汇总** | 参与统计各轮的**中位数**(可切换为**平均值**)和范围 | **合成的汇总时间线**:每一行(各阶段起止、FCP、LCP、自定义检测、DOMContentLoaded、load)分别取各轮的中位数或平均值 | 按元素归并,标出每个元素出现在几轮里 |
| **第 N 轮** | 这一轮的实际值,并标出比汇总中位数快 / 慢多少 | 这一轮的实际时间线 | 这一轮自己的候选 |

- **汇总时间线是合成的,不是某一次真实的加载**:各行的数值来自不同的轮次,可能出现在真实加载中不会有的先后关系。想看真实的一次,请选某一轮。合成后的 TTFB / FCP / LCP / 各检测的数值与卡片完全一致(已用全部历史记录对照)。
- 汇总的 LCP 行:最终元素取各轮中出现次数最多的那个,时间取各轮最终 LCP 时间的统计值;只在个别轮出现的候选元素会单独列出,并标注“x/y 轮”。
- 汇总时可以取消勾选某一轮的“参与统计”(例如首轮受 DNS / 连接冷启动影响)。数据仍然保留,随时可以恢复;至少保留一轮。排除只在当前界面有效,不会修改已保存的结果文件。
- 默认用中位数:平均值容易被偶发的慢轮次拉高。悬浮卡片里始终同时给出两者。
- **参考画面不随范围变化。** 画面来自单独的一轮录屏(为了避免录屏影响常规轮的耗时),只有这一轮有画面。元素表随范围变化;点击表格里的一行,会在参考录屏里找到同一个元素并画框,参考录屏里没有这个元素时会明确提示。
- 结果顶部的提醒标签始终按汇总计算,不受单轮视图影响。

## 结果页顶部的提醒

结果顶部会汇总需要注意的问题,悬停看明细,部分可点击跳转:

| 提醒 | 触发条件 |
|---|---|
| 只有 N 轮有效,中位数不可靠 | 有效轮数少于 3 |
| 第 N 轮明显偏慢 | 样本不少于 3 轮时,某轮的 TTFB / FCP / LCP 超过中位数 1.5 倍且至少多 150 ms |
| 最终的 LCP 元素被遮挡 | 至少一半的有效轮里,最终 LCP 元素被其他元素盖住 |
| LCP / FCP 元素在各轮间不一致 | 各轮的元素不是同一个,此时各轮的时间不可直接比较 |
| 检测没有命中 / 只在部分轮命中 | 自定义检测的条件在超时前不成立 |
| 测量失败 / 页面发生了跳转 | |

## 数据从哪里来、能识别什么、不能识别什么

所有数值都来自 Chrome 自己报告的标准接口,工具不做估算:

| 数据 | 来源 | 说明 |
|---|---|---|
| TTFB、HTML 收完、DNS、连接、domInteractive、DOMContentLoaded、load | `PerformanceNavigationTiming` | 毫秒级,准确 |
| 每个请求的下载起止、`<script>` 的 async / defer 属性 | Resource Timing + DOM | 下载时间准确;脚本执行耗时没有记录 |
| FP / FCP | `PerformanceObserver`(`paint`) | 准确 |
| LCP 及候选元素 | `PerformanceObserver`(`largest-contentful-paint`) | 时间取渲染时间;跨域图片没有 `Timing-Allow-Origin` 时浏览器只能给出加载完成时间,工具会标出“时间来源”并提醒 |
| 渲染阻塞资源 | Resource Timing 的 `renderBlockingStatus`(Chrome 的标记) | 见下 |
| 网络请求类检测 | Resource Timing | 精确 |
| 选择器 / 文字 / JS 表达式类检测 | 工具自己的观察逻辑(MutationObserver + 逐帧检查) | 约 1 帧的误差 |
| LCP 是否被遮挡 | 工具自己的判断(`elementFromPoint` 采样) | 启发式,可能判断不准 |
| 参考画面 | CDP 录屏 | 与页面时间线属于两个时钟,约差一两帧 |

**渲染阻塞资源**:只显示被 Chrome 标记为渲染阻塞的**网络请求**,包括 `<head>` 里的样式表、同步脚本、`@import` 引入的样式表。已用构造页面验证:`async` / `defer` / `module` 脚本、`media` 不匹配的样式表不会被误标。

**以下情况工具无法识别**,发生时界面会明说,不会写成“没有阻塞”:
- 内联脚本、内联样式的执行
- 样式计算与布局
- 字体加载(我的构造没有复现字体拖慢首屏,所以不能下结论)
- 主线程繁忙

当最后一个阻塞资源结束(或没有阻塞资源时 HTML 收完)到 FCP 之间超过 150 ms,界面会提示“这段时间无法识别原因”。

**测量环境**:每轮全新浏览器上下文(冷 HTTP 缓存),不限速,在本机本网络下测量;操作系统的 DNS 缓存、CDN 和服务端缓存不会被清除,所以第一轮往往更慢。数值代表“这台机器上的这次测量”,不代表真实用户的体验。Chrome 会自动更新,跨日期对比时请留意头部显示的 Chrome 版本。

## 已知限制

- **FCP 对应的元素是推断值。** 浏览器不提供这个信息,这里取与 FCP 同一时刻(±25 ms)出现的最早 LCP 候选。
- **LCP 元素可能不稳定**,也可能被其他元素遮住(例如不透明的加载遮罩),这时画面上看不到它,但浏览器仍计为 LCP。工具会检测并提示:对元素可见区域取 5 个点调用 `elementFromPoint`,至少 3 个点的最上层元素不是它自己(或后代)就判定为被遮挡。`pointer-events: none` 的覆盖层、半透明遮罩可能判断不准。
- 画面标注来自单独的一轮录屏,与统计用的轮次不是同一次加载;录屏可能影响耗时。
- 目前没有网络 / CPU 限速。
- 只测量页面加载,不包含服务端内部阶段(计划在后续版本中加入)。
- 目前只在 macOS + Chrome 上验证过;Windows / Linux 的 Chrome 自动查找依赖 Playwright 的 `channel: 'chrome'`,未测试。

## 安全

服务只监听 `127.0.0.1`,校验 `Host` 头(防 DNS 重绑定),写操作要求同源并带自定义请求头(防其他网页向本机发请求)。只接受 `http` / `https` 网址。界面中来自被测页面的文字一律以纯文本渲染。

## 界面技术

界面使用 [Preact](https://preactjs.com/) 和 [htm](https://github.com/developit/htm),**没有构建步骤**:浏览器通过 import map 直接加载 `ui/vendor/` 下的单文件模块(附各自的许可证文本:Preact 为 MIT,htm 为 Apache-2.0)。

```
ui/
  index.html         入口(含 import map)
  main.js            应用与状态
  components/        Form / Summary(指标卡)/ Timeline(瀑布时间线)/ Shot(画面与元素表)/ Tooltip(悬浮卡片)
  lib/               格式化、数据模型、说明文字、接口调用
  vendor/            preact / hooks / htm
```

时间线是自己用 HTML 和 CSS 画的,没有使用图表库:行里混合了网络阶段、里程碑和自定义检测,现成的瀑布图库都是围绕请求设计的。
